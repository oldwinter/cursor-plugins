# Slack 对话

## 这个来源包含什么

- 问题和决策的实时讨论
- 做出救火决策的 incident 频道
- 辩论过取舍的设计讨论串
- 资深工程师答过但没进文档的问题
- 解释某物为何被重提的合并后讨论
- DM（通常不可搜，相应调整 scope）

*真正的*决策常发生在 Slack，尤其是不值得写文档的小改动。它也是最易逝的来源：thread 会被删、频道会被归档、搜索质量随时间下降。

## 怎么搜

Slack MCP 工具各不相同。先看哪个 Slack MCP 可用并检查它的 tool schema。可能需要 `mcp_auth`。认证失败就停下，报告缺口。

1. **按作者限定搜索。** PR 作者在 PR 合并日前后的消息。大幅收窄范围，常一击命中。
2. **功能名和关键符号的关键词搜索。** 包括拼错和口语说法。
3. **PR URL 搜索。** PR 被 review 或讨论时常被贴到 Slack。搜 PR URL（或只搜 `/pull/<number>`）。
4. **错误串搜索。** 代码处理某个具体错误的话，搜那个错误串。incident 串常会浮出。
5. **频道限定搜索。** 收窄到可能的频道：
   - `#eng-*`：工程讨论
   - `#proj-*`：项目频道
   - `#incident-*` / `#sev-*`：incident 频道
   - owning team 的专属频道
   - 设计评审频道
6. **thread 遍历。** 找到相关消息后拉整个 thread。决策常在回复里。

## 这里什么样的证据算好

- 明确辩论过取舍的 thread（"I was going to use A but B is better because..."）
- 描述这段代码防的那个 bug 的 incident 频道消息
- reviewer 的提问加作者或 lead 的权威回答
- 提到某次做出决策的会议
- 产品经理或面向客户的工程师解释某个客户要求的消息

## 常见坑

- **频道考古极限。** 很老的消息可能因保留策略已消失。某日期之前什么都找不到时，记下这个 retention 断崖。
- **DM 不可搜。** 很多决策发生在搜不到的 DM 里。你会漏掉它们，这是已知局限。
- **把玩笑当"决策"。** Slack 很随意。"Lol just do the thing" 不是决策，即使它先于 commit。找经过考虑的讨论。
- **单条消息的语境坍缩。** 脱离 thread，单条消息读起来常不是一个意思。永远拉整个 thread。
- **认证失败。** MCP 没认证就停。别编发现。报告 Slack 不可搜。

## 返回什么

每个相关 thread：
- 频道名
- permalink 或 thread ID
- 参与者
- 讨论的日期范围
- 关键引文（逐字）附归属
- 上下文：它属于哪个 thread/incident/讨论
