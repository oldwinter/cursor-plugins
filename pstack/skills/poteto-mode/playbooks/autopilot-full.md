### Autopilot-full

**你拥有判定，永远不拥有 PR。每个 PR 一个 owner 从 build 开到 merge，没有你干净的 swarm 判定什么都不许合。** 用于 "autopilot this queue"、"full autopilot"、每 PR 一 owner 的工程。Orchestrate 跑常设工程：coordinator 自己落已验证的工作、worker 从不合并。这里每个 PR 的 owner 走完整个生命周期直到合并，root 只保留验证、会签和审计。

1. **标出 operator 的条目并遵守 state-then-wait。** operator 点名的条目留在 operator 手里：operator review、operator 点击，没有 owner 合它。operator 要你陈述协议或计划时，交付陈述然后停——只有 operator 明确说 go 才开始执行。那一声 go 上，武装一个带完整工程目标的 `/goal`。goal 跨回合延续直到队列清空。
2. **每 PR spawn 一个 owner，带全生命周期和早期轨迹。** 工程只解析一次 forge。GitHub CLI（`gh`）是默认。`command -v origin` 成功且 Origin 能解析该仓库时，用 `origin pr ...` 做 PR 的 create、edit、view、watch 和 merge。否则留在 `gh` 并记录回退。绝不要求 Graphite（`gt`）。每 PR 一个 Cursor cloud agent，拥有：build、首次推送、ready 状态的 PR、真实产物上的自证（**prove-it-works** 原则 skill）、按 `../references/bugbot-triage.md` 的怀疑式 Bugbot 分诊、过一遍 slop 清理（`cursor-team-kit` plugin 的 `deslop` skill，`/deslop`）、`/no-comments`（**no-comments** skill）、rebase 到当前 trunk、babysit 到绿（`playbooks/babysit.md`）、以及合并本身。约 15 分钟内，每个 owner 按 **show-me-your-work** skill 开一条 `decisions.tsv` 轨迹、推上第一个 branch 快照、把 PR 开成 ready——绝不用 draft。PR 开在自证之前，让 URL、决策和 check 构成持久轨迹。`decisions.tsv` 保持未提交、随报告交回。rebase 永远在 babysit 之前，从不等漂移或冲突。合并是唯一 owner 不许独自走的步骤——步骤 4 给它上闸。
3. **owner 真并行，绝不叠 stack。** PR 自包含时多个 owner 同时跑：每个 branch 一个写者、文件不相交、跨 PR 漂移由 rebase 吸收。只有真正重叠的工作串行。自包含 PR 直接从 main 拉 branch，有时序的工作 merge-再-branch。一个例外：必须拆真正有依赖的改动的 owner 可以持有短的私有 base-branch stack。
4. **每个 merge-ready 头在合并前经 swarm 验证。** 在 owner 的 merge-ready head SHA 上，按 **swarm** skill fan out 并行独立 verifier，聚合成一个判定。各条道：在那个 SHA 上重跑 gate。在改动触及的真实 surface 上实机证明承重行为（按改动需要 `cursor-team-kit` 的 `control-cli` 或 `control-ui`）。审计回执和 diff，不信任 PR body。**对 trunk 的回归道。** 在当前 trunk 上跑同一个承重场景。trunk 没有该功能就记下这个事实，改为 gate diff 新增的行为加用户等待的终态，而不是假装 trunk 产得出来。实机道是地板，没有它的判定不干净。没有 root 的干净判定就没有合并。发现退回 owner 做向前修复，新 head 拿一轮新 swarm 和新判定。
5. **干净判定下 owner 合并并接下一个条目。** owner 只从刚 rebase 到 trunk 的 head 合并。merge-ready 报告是在 trunk 最新的 head 上做出的，swarm 判定钉住那个 SHA。合并前 trunk 又动了，`playbooks/shipping.md` 的 patch-id 规则管辖重验。新 head 作废判定，除非 patch-id 未变。owner 经解析出的 forge squash-merge 自己的 PR，然后从队列接下一个自包含条目。operator 的完全自主授权加 root 的干净判定，构成 babysit 永远不会有的合并授权。operator 点名的条目停在 merge-ready，等 operator 的点击。
6. **跑 root 层。** 对钉住的 gate 或预算值做一次真正的新抬高（CI 只许收紧的限制）需要你新鲜会签——只在 verifier 证明之后给。吸收已落上 main 的值是漂移，不是抬高。大约每 30 分钟对所有 owner 跑一轮审计 tick。本地 root 把每次 tick 武装成真的终端 `/loop`：循环用被监视 shell 的 30 分钟 sleep 并发出 output-notification 哨兵。cloud root 改用现有的 cloud-sleeper 唤醒链。节奏绝不交给记忆或有损的完成通知。每个 tick：用 `git show origin/main:pstack/skills/poteto-mode/playbooks/autopilot-full.md` 从 trunk 重读本 playbook，再重读武装的 `/goal`。对照两者审计运作。漂移在当 tick 修。用通用的活性或状态检查探每个 owner，收决策轨迹。只把副作用算进度：commit、push、PR 或 check 差值、store 报告。过了预期运行时间还没副作用的 lane 按卡死处理：立即解职并派替补。别等礼貌的返回。合并成批时跑一轮 retro 和合并后 bot 评论清扫。
7. **operator 说停就立即解职。** operator 的 hold 或 stand-down 作为零写命令立即到达每个 owner。owner 持有自己的 brief 直到 operator 释放。

**回复：** 队列：每个 PR 的 owner、状态、head SHA。每个判定及产出它的 swarm。合了什么、每个 owner 接了什么。给了哪些会签及为什么。开着的 operator gate。收来的决策轨迹在哪。
