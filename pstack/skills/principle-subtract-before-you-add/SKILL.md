# Subtract Before You Add（先减后加）

演进一个系统时，先移除复杂度，再构建。

**为什么：** 给复杂系统做加法会让复杂度复利。先移除留下的代码更少、暴露本质结构，而且通常让下一个设计显而易见。默认做减法。

让简化成为持续投入。离开时让设计比你来时更简单、能力更强，而表面同等或更小。

**模式：**
- 把移除排在构建之前
- 先砍再抛光（投入质量之前先到最小）
- 按观察到的用法设计，不按推测的边角情形
- 不写超出 spec 要求的投机校验器、parser 或守卫
- 简化 prompt（删掉冗余指令、过多的模板）
- 当一个引用没有新内容时删掉它，别留存根
